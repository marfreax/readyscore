# ReadyScore V19.2.1 — Actual Entitlement Access Classification

## Rule

Access classification is derived from **currently active entitlements**, never from transaction/order count or purchase history.

The source of truth is:

- active `TEST_ACCESS` + `TEST_TYPE` entitlements for the six core assessments
- active `PROFILE_ACCESS` + `FEATURE` + `CROSS_TEST_PROFILE_V1` for profiling

`listUserEntitlements()` already applies the active window (`status=ACTIVE`, `startsAt <= now`, and `endsAt` null/future) across product and add-on entitlements.

## Canonical classification

| Active core test entitlements | Profiling entitlement | Access level |
|---:|:---:|:---|
| 0 | any | FREE |
| 1 | any | SINGLE_TEST |
| 2–5 | any | CUSTOM_ACCESS |
| 6 | no | ALL_TESTS |
| 6 | yes | ADVANCE |

Core tests:

1. COGNITIVE
2. EQ
3. DISC
4. RIASEC
5. WORK_ATTITUDE
6. LEARNING_PREFERENCE

## Important behavior

- Multiple orders for the same test count as **one** active core test entitlement.
- `RESULT_ACCESS` does not increase the test count.
- Historical/inactive/revoked entitlements do not count because the source list is active-only.
- A user with 2–5 distinct active core test entitlements is `CUSTOM_ACCESS`, even if those entitlements came from multiple Single Test orders.
- `ADVANCE` requires all six active core test entitlements **and** active Cross-Test Profile entitlement.

## V19.2.1 scope

The classification is used by Access & Plans for the current access display and plan-state presentation. Existing V19.2 assessment runtime, scoring, question selection, enums, and fulfillment behavior are not changed by this classification patch.

## Validation

`pnpm v19.2.1:access-classification` covers:

- 0, 1, 2, 3, 5, and 6 active core tests
- 6 core tests + profiling
- duplicate entitlement rows not inflating the count
