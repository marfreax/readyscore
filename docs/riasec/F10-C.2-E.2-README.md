# F.10-C.2-E.2 — AssessmentType PostgreSQL Enum Reconciliation

## Problem addressed

The actual PostgreSQL runtime reported:

`invalid input value for enum "AssessmentType": "RIASEC"`

The application schema expects `RIASEC`, but the live PostgreSQL enum does not contain it.

## Safety boundary

This phase changes **only** the PostgreSQL enum:

`AssessmentType`

It does NOT:

- approve questions
- publish questions
- modify QuestionVersion
- modify Question
- create AssessmentAttempt
- modify answers
- modify results

## Verification

After replacing the ZIP:

```bash
rm -rf .next
pnpm typecheck
pnpm build
pnpm riasec:enum:check
```

The check is read-only.

If it reports `RIASEC enum value : MISSING`, apply the targeted reconciliation:

```bash
pnpm riasec:enum:reconcile -- --apply
```

Then verify again:

```bash
pnpm riasec:enum:check
```

Expected final state:

```text
AssessmentType values: FREE, PREMIUM, RIASEC
RIASEC enum value   : PRESENT
F.10-C.2-E.2 ENUM RECONCILIATION: PASS
```

Only after this passes should F.10-C.2-E.1 be rerun:

```bash
pnpm riasec:start:diagnostic
```

Then the actual runtime E2E:

```bash
pnpm e2e:riasec
```
