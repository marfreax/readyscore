# RIASEC lib reconciliation — based on uploaded `lib.zip`

## Findings

The uploaded `lib` contained the complete RIASEC work, but three contracts were
out of sync:

1. `result-adapter.ts` was constructing fields that do not exist on the actual
   `AssessmentResult` interface.
2. `runtime-dispatch.ts` had the argument order expected by the dispatcher,
   while `runtime-service.ts` still contained a separate manual RIASEC branch.
3. The RIASEC persistence adapter duplicated the existing
   `assessment-repository.ts` persistence boundary and was not part of the
   actual submit flow.

## Fix

### 1. `result-adapter.ts`

Now maps strictly to the actual v2 `AssessmentResult`:

```text
attemptId
assessmentType
assessmentConfigurationVersion
questionBankVersion
taxonomyVersion
scoringVersion
overallScore
band
status
domainScores
subdomainScores
indicatorScores
coverage
dataSufficiency
completedAt
```

RIASEC-specific measurement remains in the versioned `riasec` payload.

### 2. `runtime-dispatch.ts`

Now becomes the single RIASEC dispatch boundary.

It validates:

```text
60 total questions
10 R
10 I
10 A
10 S
10 E
10 C
60 answers
```

and then executes:

```text
scoreRiasec()
→ toAssessmentResult()
→ RIASEC_RESULT_V1
```

FREE/PREMIUM continue to use the existing generic scorer.

### 3. Persistence

Do NOT call `persistRiasecResult()` separately from runtime submit.

The existing:

```text
persistCompletedResult()
```

already persists the complete `AssessmentResult` JSON and marks the attempt
completed transactionally.

The RIASEC payload is therefore attached to the result object before that
existing persistence boundary.

## Required runtime-service change

The current uploaded `runtime-service.ts` still manually implements RIASEC
scoring. Replace that manual branch with:

```ts
const result = calculateRuntimeAssessmentResult(
  attempt.attempt.assessmentType,
  questions,
  answers,
  {
    attemptId: id,
    assessmentConfigurationVersion:
      attempt.attempt.assessmentConfigurationVersion,
    questionBankVersion: attempt.attempt.questionBankVersion,
    taxonomyVersion,
    scoringVersion: attempt.attempt.scoringVersion,
    completedAt,
  },
);
```

and import:

```ts
import { calculateRuntimeAssessmentResult } from "./riasec/runtime-dispatch";
```

Remove the direct RIASEC imports from `runtime-service.ts`.

Do not modify the generic `scoring-engine.ts`.

## Important

This package intentionally does not modify Prisma.

The uploaded `lib` already shows that the existing repository persists
`AssessmentResult` in the JSON result column. A second RIASEC repository would
create two competing persistence boundaries.
