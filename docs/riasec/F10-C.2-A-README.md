# F.10-C.2-A — RIASEC Production Lifecycle Synchronization

## Purpose

Bridge the explicitly human-approved RIASEC production manifest into the canonical
PostgreSQL `QuestionVersion` lifecycle.

## Hard gates

The script refuses all database mutation unless:

1. production manifest exists;
2. manifest status is `APPROVED_FOR_PUBLICATION`;
3. exactly 60 IDs are present;
4. IDs are unique;
5. all IDs belong to the 60 production candidates;
6. all IDs have an explicit review row;
7. mapping review is `APPROVED`;
8. content review is `APPROVED`;
9. decision is `APPROVE`;
10. human-review manifest flags are all true;
11. exactly 10 IDs exist in each RIASEC dimension;
12. all 60 `QuestionVersion` rows exist in PostgreSQL;
13. every row currently has `mappingStatus = MAPPED`.

Only after all gates pass does the script mutate the explicit 60 IDs:

```text
MAPPED -> APPROVED
APPROVED -> PUBLISHED
```

No other question is modified.

## Important

This phase does not auto-approve the 84 candidate questions.

If the manifest is still:

```text
PENDING_CONTENT_REVIEW
```

or otherwise not explicitly approved, the script exits without database mutation.

## Run

```bash
pnpm riasec:publish
```

Then:

```bash
pnpm e2e:riasec
```

The lifecycle sync is intentionally separated from the actual runtime E2E.
