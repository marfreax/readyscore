# PHASE 3.0-D.1-F.10-B.8 — RIASEC Human Review Manifest Reconciliation

## Objective

Convert the human review decisions for the 84 RIASEC candidates into a final
60-question production manifest.

This phase does **not** mutate PostgreSQL.

It only reconciles:

```text
84 candidate questions
        ↓
human review decisions
        ↓
60 fully approved question IDs
        ↓
production manifest
```

## Canonical locations

### Human review decision file

```text
data/question-bank/review/
└── RIASEC_QB_V1_HUMAN_REVIEW_DECISIONS_84.csv
```

### Final production manifest

```text
data/question-bank/production/
└── RIASEC_QB_V1_APPROVED_PRODUCTION_MANIFEST.json
```

### Runtime lifecycle

```text
lib/assessment/riasec/
└── production-lifecycle.ts
```

### Reconciliation script

```text
scripts/
└── reconcile-riasec-human-review.ts
```

## Review decision requirements

A question is considered fully approved only when ALL THREE fields are:

```text
mapping_review_status = APPROVED
content_review_status = APPROVED
decision = APPROVE
```

Anything else is not approved.

This deliberately prevents a partially reviewed question from entering the
production manifest.

## Production quota

The final manifest must contain exactly:

```text
R = 10
I = 10
A = 10
S = 10
E = 10
C = 10
────────
Total = 60
```

## Reserve replacement

A RESERVE question may be used if a TARGET question is rejected/revised,
but it must pass the exact same review gate.

The script does NOT automatically select reserve questions.

Human review decides the replacement.

## Initial state

The included review file is intentionally:

```text
84 rows
mapping_review_status = PENDING_REVIEW
content_review_status = PENDING_REVIEW
decision = empty
```

Therefore the first execution is expected to report that human review is
incomplete.

The included production manifest remains:

```text
status = PENDING_HUMAN_REVIEW
questionIds = []
```

## Review workflow

Open:

```text
data/question-bank/review/RIASEC_QB_V1_HUMAN_REVIEW_DECISIONS_84.csv
```

For each item, fill:

```text
mapping_review_status
content_review_status
decision
reviewer_note
```

Use:

```text
APPROVED
```

only when the mapping/content has actually been reviewed.

Use:

```text
REVISE
REJECT
```

when applicable.

## Execute reconciliation

From ReadyScore root:

```bash
pnpm tsx scripts/reconcile-riasec-human-review.ts
```

### Before review

Expected:

```text
Review rows: 84
Fully approved rows: 0

No production manifest generated.
Human review is incomplete.
```

### After valid review

Expected:

```text
Review rows: 84
Fully approved rows: 60

R: 10
I: 10
A: 10
S: 10
E: 10
C: 10

Status: APPROVED_FOR_PUBLICATION

IMPORTANT: PostgreSQL was NOT mutated.

F.10-B.8 HUMAN REVIEW RECONCILIATION: PASS
```

## Safety

The script rejects:

- fewer than 60 approved items
- more than 60 approved items
- duplicate IDs
- IDs outside the current Question Bank
- non-RIASEC items
- wrong dimension quotas
- invalid review status values

The script never calls:

```text
approveMapping
approveQuestion
publishQuestion
```

and therefore cannot publish anything.

## Exit criteria

- [ ] All 84 candidates reviewed.
- [ ] Exactly 60 fully approved.
- [ ] Exactly 10 approved per dimension.
- [ ] Any reserve replacement is explicitly reviewed.
- [ ] Production manifest generated.
- [ ] Manifest status = APPROVED_FOR_PUBLICATION.
- [ ] PostgreSQL remains unchanged.
