# F.10-C.2-F — RIASEC Result Payload Reconciliation

This phase follows the actual v3 measurement/result architecture.

The persisted `AssessmentResult.result` is the immutable JSON snapshot. The RIASEC-specific measurement is intentionally carried inside the versioned `riasec` payload while the generic v2 `AssessmentResult` contract remains unchanged.

Canonical runtime shape:

```text
AssessmentResult
└── riasec
    ├── contractVersion: RIASEC_RESULT_V1
    └── measurement
        ├── testType: RIASEC
        ├── scoringVersion: RIASEC_SCORE_V1
        ├── dimensionScores: R/I/A/S/E/C
        ├── rankedDimensions
        ├── topCode
        ├── coveragePercent
        └── quality
```

This phase does NOT flatten RIASEC scores into generic `scores`, because the roadmap explicitly separates test-specific result semantics from the generic v2 result contract.

The diagnostic reads the persisted JSON snapshot and validates the actual canonical payload. It performs no mutation.

Verification:

```bash
rm -rf .next
pnpm typecheck
pnpm build
pnpm riasec:result:check
pnpm e2e:riasec
```

The E2E assertion validates the real HTTP submit response against the same canonical `RIASEC_RESULT_V1` payload.
