## Review decision model

Each item has two independent review dimensions:

### 1. Mapping review

Check:

```text
domain
subdomain
indicator
```

Decision:

```text
APPROVE
REVISE
REJECT
```

### 2. Content review

Check:

```text
construct fit
wording quality
ambiguity
reverse-item quality
```

Decision:

```text
APPROVE
REVISE
REJECT
```

An item can only progress when both mapping and content review are approved.

## Recommended review columns

Use these values:

```text
construct_fit:
  PASS / FAIL

wording_quality:
  PASS / FAIL

ambiguity_flag:
  NONE / REVIEW

reverse_item_quality:
  PASS / FAIL / N-A

decision:
  APPROVE / REVISE / REJECT
```

## Production selection rule

The 60 TARGET items are **production candidates**, not automatically approved production items.

After review:

```text
APPROVED TARGET
    ↓
must retain 10 approved items per dimension
    ↓
RIASEC production set = 60
```

If a TARGET item is rejected or revised beyond usability, replace it with an approved RESERVE item from the same dimension.

Therefore:

```text
R: 10 production items
I: 10 production items
A: 10 production items
S: 10 production items
E: 10 production items
C: 10 production items
```

must remain true at the production gate.

## Important psychometric boundary

This review gate is a content/mapping gate.

It does NOT establish:

- reliability
- item discrimination
- factor structure
- convergent validity
- criterion validity

Those require pilot data and are outside this immediate database lifecycle step.
