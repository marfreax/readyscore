# F.10-B.8-B — RIASEC Content Review & Production Selection

Based on the actual 84-question RIASEC candidate bank.

This phase separates:

1. source candidate role (`TARGET` / `RESERVE`)
2. substantive content review
3. final production approval

The source's 60 TARGET items are copied to:

```text
data/question-bank/production/RIASEC_QB_V1_PRODUCTION_CANDIDATE_60.csv
```

but remain:

```text
approval_status = NOT_APPROVED
```

The final manifest remains empty until the review CSV contains exactly:

```text
mapping_review_status = APPROVED
content_review_status = APPROVED
decision = APPROVE
```

for exactly 60 items, with exactly 10 per RIASEC dimension.

Run:

```bash
pnpm tsx scripts/reconcile-riasec-content-review.ts
```

No database mutation occurs in this phase.

Expected initial result:

```text
Review population : 84
Fully approved    : 0
...
CONTENT REVIEW INCOMPLETE
No production manifest generated.
No database mutation performed.
```

After substantive review, the script generates:

```text
data/question-bank/production/RIASEC_QB_V1_APPROVED_PRODUCTION_MANIFEST.json
```

with status:

```text
APPROVED_FOR_PUBLICATION
```

Only then can F.10-B.9 execute PostgreSQL lifecycle mutation.
