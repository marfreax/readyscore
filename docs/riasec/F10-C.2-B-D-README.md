# F.10-C.2-B/D — RIASEC Production Approval Pipeline

This batch combines the non-database portions of:

- F.10-C.2-B — Human Review Decision Capture
- F.10-C.2-C — Production Manifest Generation
- F.10-C.2-D — PostgreSQL Publication Reconciliation

## Review surface

Open:

`/admin/riasec-review`

The workspace presents all 84 candidates and allows a human reviewer to mark each:

- APPROVE
- RESERVE
- REJECT

It exports a JSON review package. The browser does not mutate PostgreSQL.

## Apply the human decision package

```bash
pnpm riasec:review:apply /path/to/RIASEC_QB_V1_HUMAN_REVIEW_DECISIONS.json
```

The script requires all 84 decisions and refuses incomplete review.

It then writes:

`data/question-bank/review/RIASEC_QB_V1_HUMAN_REVIEW_DECISIONS_84.csv`

## Generate the production manifest

```bash
pnpm riasec:manifest
```

Hard gates:

- exactly 60 APPROVE
- exactly 10 per RIASEC dimension
- every approved ID belongs to the 60 production candidate set
- mapping approval remains explicit
- content approval is explicit

No database mutation occurs.

## Publish only after the manifest is explicitly approved

```bash
pnpm riasec:publish
```

That command is the existing F.10-C.2-A gate. It is the only step in this batch that mutates PostgreSQL.

## Final runtime test

```bash
pnpm e2e:riasec
```

The expected successful chain is:

human review
→ manifest
→ PostgreSQL publication
→ 60-question runtime selection
→ answers
→ submit
→ RIASEC result.

No step auto-approves human content decisions.
