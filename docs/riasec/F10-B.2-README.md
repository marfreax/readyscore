# F.10-B.2 — RIASEC Question Bank Draft Import

## Objective

Import all 84 RIASEC candidate items into the existing PostgreSQL Question Bank as **DRAFT**.

This does not publish anything and does not make the items runtime-eligible.

Expected:

- 84 total
- 60 TARGET
- 24 RESERVE
- R/I/A/S/E/C each: 10 TARGET + 4 RESERVE
- `QuestionVersion.status = DRAFT`
- `QuestionVersion.mappingStatus = MAPPED`

`MAPPED` here means the candidate CSV already contains a mapping. It does **not**
mean the question is approved or eligible for assessment runtime.

## Files

```text
data/question-bank/source/RIASEC_QB_V1_FULL_84_CANDIDATE.csv
scripts/import-riasec-qb-v1-draft.ts
```

## Preconditions

From the ReadyScore project root:

```bash
pnpm db:generate
pnpm typecheck
```

Do not run a migration for this import. The current Prisma schema already
contains the Question / QuestionVersion lifecycle required for DRAFT import.

## Execute

```bash
pnpm tsx scripts/import-riasec-qb-v1-draft.ts
```

The script is intentionally append-only:

- It refuses duplicate IDs in the CSV.
- It refuses any ID that already exists in the database.
- It runs the complete import inside one transaction.
- If one row fails, the transaction is rolled back.

```text

```

## Verify in Prisma Studio

```bash
pnpm db:studio
```

Filter Question / QuestionVersion by:

```text
domain = R
domain = I
domain = A
domain = S
domain = E
domain = C
```

and confirm:

```text
status = DRAFT
```

Do not approve or publish these questions yet.

## Why this is safe

The existing runtime query only considers:

```text
status = PUBLISHED
mappingStatus = APPROVED
```

so these 84 records cannot enter an assessment merely by being imported.
