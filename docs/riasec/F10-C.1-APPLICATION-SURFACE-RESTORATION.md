# PHASE 3.0-D.1-F.10-C.1 — Application Surface & Runtime Route Restoration

## Baseline

`RS-v2_18B.zip`

## Problem confirmed from the actual source

The baseline contained the assessment runtime and `AssessmentRunner`, but only:

```text
app/api/assessment/start/route.ts
```

There were no application pages for:

- `/`
- `/app`
- `/trial`
- `/trial/free`
- `/trial/premium`
- `/trial/riasec`
- `/admin/question-bank`
- `/result/[attemptId]`

The existing `AssessmentRunner` also referenced runtime routes that were absent.

## Implemented

### Application surface

```text
app/
├── page.tsx
├── layout.tsx
├── globals.css
├── app/page.tsx
├── trial/
│   ├── free/page.tsx
│   ├── premium/page.tsx
│   └── riasec/page.tsx
├── admin/question-bank/page.tsx
└── result/[attemptId]/page.tsx
```

### Runtime routes

```text
app/api/assessment/[attemptId]/
├── route.ts
├── answer/route.ts
├── submit/route.ts
└── abandon/route.ts
```

These routes are backed by the existing `lib/assessment/runtime-service.ts` and therefore preserve the existing PostgreSQL attempt/question/answer/result contract.

### RIASEC

`AssessmentRunner` was extended from:

```text
free | premium
```

to:

```text
free | premium | riasec
```

No RIASEC scoring engine was replaced.

## Database mutation

This phase does not perform automatic question-bank lifecycle mutation.

## Validation

Run:

```bash
pnpm typecheck
pnpm build
```

Then:

```bash
pnpm dev
```

Verify:

```text
http://localhost:3000/
http://localhost:3000/app
http://localhost:3000/trial/riasec
http://localhost:3000/admin/question-bank
```

The expected architectural outcome is that these routes no longer return framework 404s.
