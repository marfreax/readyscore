# ReadyScore v3 — PHASE 3.0-D.1-F.9.3
# V2 Baseline Recovery & RIASEC Preservation

**Status:** RECOVERY / MERGE GATE  
**Baseline source:** `RS-v2(2).zip`  
**Purpose:** Restore the complete ReadyScore v2 application tree while preserving the already-validated RIASEC F.4–F.9.2 work.

---

## 1. Objective

The current local project was found to contain only:

```text
app/api/assessment/start/route.ts
```

under `app/`, which caused the previously existing UI and API routes to return 404.

The uploaded `RS-v2(2).zip` is now the baseline source for recovery.

This phase therefore has one purpose:

```text
V2 COMPLETE BASELINE
        +
RIASEC F.4–F.9.2
        ↓
RESTORED V2 + RIASEC
```

This is **not** a new product feature.

---

## 2. Recovery Principle

The baseline archive is treated as the source of truth for files that belong to the original v2 application.

RIASEC work already introduced under:

```text
lib/assessment/riasec/
```

must be preserved.

The merge rule is:

```text
BASELINE V2
    ↓
restore missing baseline files
    +
preserve RIASEC-specific files
    ↓
reconcile shared files explicitly
```

We must NOT blindly overwrite shared files.

---

## 6. Recovery Strategy

### Step 1 — Snapshot current state

Before recovery:

```bash
cp -R . ../ReadyScore-before-F9.3
```

Do not delete the current project.

### Step 2 — Extract baseline outside the project

Extract:

```text
RS-v2(2).zip
```

to a temporary directory.

Do not extract directly over the project.

### Step 3 — Recover non-conflicting baseline files

Copy baseline files that are missing locally.

Typical categories:

```text
app/**
components/**
lib/**/*
prisma/**/*
```

except explicitly shared files.

### Step 4 — Reconcile shared files

Compare:

```text
baseline
vs
current
```

for:

```text
runtime-service.ts
scoring-engine.ts
types.ts
question-engine.ts
assessment-repository.ts
schema.prisma
```

No automatic overwrite.

### Step 5 — Preserve RIASEC

Ensure current:

```text
lib/assessment/riasec/
```

remains present.

### Step 6 — Restore UI/API tree

Verify routes such as:

```text
/trial
/app
/login
/register
/account
/account/history
/result/[attemptId]
/assessment/premium
/admin/question-bank
```

and their corresponding API routes.

## 8. Verification Matrix

After recovery:

### A. Route inventory

```bash
find app -maxdepth 5 -type f | sort
```

```text
app/api/assessment/start/route.ts
```

### B. RIASEC inventory

```bash
find lib/assessment/riasec -maxdepth 2 -type f | sort
```

### C. Prisma

```bash

```

### D. TypeScript

```bash
rm -rf .next

```

### E. Build

Only after typecheck:

```bash
pnpm build
```

---

## 10. Failure Classification

### F9.3-A — Baseline Recovery Failure

Missing baseline files/routes.

### F9.3-B — Shared File Reconciliation Failure

Baseline and RIASEC versions of a shared file conflict.

### F9.3-C — Type Contract Failure

`pnpm typecheck` fails.

### F9.3-D — Build Failure

`pnpm build` fails.

### F9.3-E — Regression

Existing v2 functionality breaks after recovery.
