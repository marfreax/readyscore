
## Objective

Create a RIASEC-specific production lifecycle boundary that safely moves an explicitly human-approved set of 60 questions through the existing PostgreSQL lifecycle:

```text
DRAFT + MAPPED
      ↓
MAPPING APPROVED
      ↓
QUESTION APPROVED
      ↓
PUBLISHED
```

The existing generic repository functions remain intact.

## Lifecycle safety

The implementation uses a single PostgreSQL transaction with:

```text
SERIALIZABLE
```

and verifies before mutation:

- exactly 60 IDs
- unique IDs
- all IDs exist
- all are RIASEC
- exactly 10 per dimension
- latest QuestionVersion is DRAFT
- mapping is MAPPED or REVIEW_REQUIRED
- subdomain exists
- indicator exists
- text exists
- weight > 0
- scale has 5 values
- scoringKey has 5 values

If any check fails:

```text
ROLLBACK
```

No partial RIASEC publication is allowed.
