## Recommended order

### 1. Validate content package

```bash
python3 validation/validate-riasec-qb-v1.py
```

Expected:

```text
RIASEC_QB_V1 VALIDATION: PASS
```

### 2. Integrate RIASEC taxonomy

Apply:

```text
patches/F10-RIASEC-TAXONOMY.patch
```

This allows the existing CSV mapping pipeline to recognize R/I/A/S/E/C.

### 3. Isolate the RIASEC pool

Apply:

```text
patches/F10-RIASEC-POOL-ISOLATION.patch
```

This is mandatory before publishing RIASEC items.

Without it, the current FREE selection path can see all published eligible questions and could accidentally select RIASEC items.

### 4. Import target + reserve

Use the existing Question Bank import pipeline.

Import:

```text
RIASEC_QB_V1_FULL_84_CANDIDATE.csv
```

in `append` mode.

The existing repository intentionally creates imported records as:

```text
DRAFT
```

so do not modify that behavior.

### 5. Review and publish

Do NOT manually update the database to PUBLISHED.

Use the existing lifecycle:

```text
DRAFT
→ mapping/content review
→ APPROVED
→ PUBLISHED
```

Target production set:

```text
60
```

Reserve:

```text
24
```

Reserve items must remain outside the normal selection target.

## Important implementation limitation

The current Question/QuestionVersion schema does not have an explicit `testType` field.

This package therefore uses:

```text
RIASEC domains = R/I/A/S/E/C
```

and the pool-isolation patch to prevent cross-test contamination.

This is a safe v1 bridge, but the long-term v3 architecture should add an explicit test/instrument ownership field to QuestionVersion (or an equivalent QuestionBank entity) before multiple instruments such as DISC, IQ, EQ, and AQ are all active.
