# PHASE 3.0-D.1-F.9.1 — Runtime Dispatch Reconciliation

## Source-of-truth findings

The current v2 runtime has a single scoring call in:

```text
lib/assessment/runtime-service.ts
```

and currently calls:

```text
calculateResult(...)
```

directly.

The generic scorer must remain the FREE/PREMIUM path.

RIASEC therefore needs an explicit dispatch boundary.

## Implementation

New file:

```text
lib/assessment/riasec/runtime-dispatch.ts
```

The dispatch contract is:

```text
free / premium
    ↓
existing calculateResult()

riasec
    ↓
scoreRiasec()
    ↓
toAssessmentResult()
```

## Important

This phase does NOT modify `runtime-service.ts`.

It creates and validates the single dispatch boundary first. Runtime-service wiring is the next controlled change.

## RIASEC dimension source

For the current v2 `Question` contract, the RIASEC adapter uses:

```text
Question.domain
```

as the RIASEC dimension and validates it against:

```text
R I A S E C
```

No inference from subdomain or indicator is performed.

## Exit criteria

- [ ] typecheck passes
- [ ] dispatch test passes
- [ ] FREE/PREMIUM generic scorer remains untouched
- [ ] RIASEC cannot silently fall through to generic scoring
- [ ] runtime-service integration is performed only after this boundary passes
