# ReadyScore V17.10 — Question Configuration Model

## Baseline

Built from the latest V17.10 runtime-alignment baseline after the preflight failure was diagnosed and from the agreed product model.

## Product decisions locked in this package

Current assessment catalog:

- FREE
- RIASEC
- DISC
- EQ
- COGNITIVE

Premium is not part of the current product/runtime architecture.

## Operational model

Question Bank and Assessment Setting are independent.

```text
Question Bank
  └─ any number of questions may be added

Assessment Setting
  ├─ composition per taxonomy node
  ├─ total = sum(composition)
  └─ readiness = published eligible pool vs required composition

Runtime
  └─ select exactly the configured total from the complete published pool
```

Example:

```text
DISC setting
D=10 I=10 S=10 C=10
Total=40

Add 40 more published DISC questions
→ pool becomes 80
→ assessment still returns 40
→ the 40 are selected from the full 80
```

Changing the setting to `20/20/20/20` creates a new configuration version and future attempts return 80 questions. Existing attempts remain immutable.

## Admin model

Admin normally operates only two things:

1. Question Bank — create, validate, approve, publish questions.
2. Assessment Setting — define composition.

QuestionPackage/QuestionPackageVersion remains an internal runtime artifact maintained by the system.

## Safety

- Preflight is read-only.
- Alignment is transactional.
- No question status is auto-promoted.
- No historical attempt is rewritten.
- Published question pool is the only runtime content source.
- Configuration changes affect future attempts only.

## V17.10.1 Admin UI finishing

- Admin configuration list is scoped to the five canonical operational configuration codes.
- Legacy v2, Premium, E2E, and other non-canonical configuration records remain in the database but are excluded from operational Admin UI/API actions.
- Summary statistics are scoped to the same canonical set.
- CREATE is restricted to the canonical assessment type/code contract.
- When all five operational configurations exist, Admin creates new versions instead of new assessment settings.
- Readiness/action endpoints reject non-operational historical configurations without modifying their records.
- Question Package remains an internal runtime artifact and is not an operational Admin navigation item.
- No migration or historical record mutation is included.
