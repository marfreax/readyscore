# ReadyScore V14.4 — Access & Plans / Midtrans UI FIX2

## Purpose

Remove the intermediate ReadyScore checkout screen from the customer purchase journey and make Access & Plans purchase CTAs concise and actionable.

## Customer purchase behavior

- All purchasable CTA buttons use the label `Beli`.
- Owned assessment access is represented by a disabled `Sudah dibeli` button.
- Lower-tier capabilities already included by the current paid tier remain disabled as `Sudah termasuk`.
- Current paid plan remains disabled as `Sudah dibeli`.
- Higher available plans use `Beli`.
- Single Test buttons continue to identify the selected assessment through the query parameter, but the customer no longer sees an intermediate checkout form.

## Payment handoff

Clicking `Beli` navigates to `/checkout/[productId]` only as an implementation handoff route. That route immediately:

1. loads the active commercial catalog,
2. creates the ReadyScore commercial order,
3. creates/reuses the Midtrans payment attempt,
4. obtains the provider `redirectUrl`, and
5. redirects the browser directly to the Midtrans Snap payment page.

The customer should therefore see Midtrans's payment page, where the available sandbox payment methods are presented by Midtrans.

## Integrity boundary

No entitlement is granted by the UI click or by opening the handoff route. Entitlement remains dependent on verified payment and the existing V14.3 fulfillment/access boundary.

## Regression contract

The V14.4 static/E2E contracts were updated to reject the obsolete UI labels:

- `Checkout belum terhubung`
- `Choose Single Test`
- `Pilih Assessment`
- `Beli dengan Midtrans`
- `Upgrade dengan Midtrans`
- `Bayar dengan Midtrans`
- `Menghubungkan ke Midtrans…`

The direct payment handoff contract requires the commercial checkout/payment APIs and `window.location.assign(redirectUrl)`.
