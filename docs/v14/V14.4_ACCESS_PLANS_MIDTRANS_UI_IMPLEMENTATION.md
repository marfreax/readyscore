# V14.4 Access & Plans — Midtrans UI Integration

## Objective

Make every customer-facing purchase CTA on `/access` use the V14 commercial checkout → Midtrans flow, and make ownership state explicit.

## Implemented

- Removed Access & Plans purchase dependence on legacy Scalev checkout links.
- Single Test CTAs now route to `/checkout/product-basic?testType=...` for IQ, EQ, DISC, and RIASEC.
- BASIC checkout now persists the selected assessment type in `CommercialOrder.assessmentTypeSnapshot`.
- All Tests routes to `/checkout/product-medium`.
- All Tests + Profiling routes to `/checkout/product-advance`.
- Checkout page creates the commercial order, creates the Midtrans payment, and redirects to the Midtrans payment URL.
- Owned assessment purchase CTAs are disabled and labeled `Sudah dibeli`; the assessment start action remains available separately.
- Owned/current plans are rendered as disabled `Sudah dibeli`; lower tiers included by the current tier are disabled as `Sudah termasuk`.
- Available plans and assessments use explicit Midtrans purchase labels.
- V14.4 static validation now rejects obsolete Scalev/disconnected CTA markers and requires the new Access & Plans contracts.
- V14.4 E2E now checks available Access & Plans purchase links before purchase and owned/upgrade states after fulfillment.
- Midtrans order-reference mismatch errors now retain strict reference validation while exposing safe diagnostic fields for sandbox troubleshooting.

## Validation performed in this build

- `node --check v14/tests/e2e-v14-4-commercial-launch.mjs` — PASS.
- `node --experimental-strip-types scripts/validate-v14-4-commercial-launch.ts` — PASS.
- Full `pnpm typecheck` / production E2E were not executable in the build container because project dependencies could not be installed from the npm registry.
- Real Midtrans sandbox validation remains an environment/runtime test and must be run after deploying/running this build with the project's `.env` credentials.

## Non-goals

- No scoring, measurement, assessment selection, timer, or result architecture changes.
- No database migration.
- No replacement of Midtrans with another payment provider.
- No weakening of payment verification or webhook integrity checks.
