# ReadyScore V14.4 — Payment Success & Automatic Unlock FIX2

## Purpose

Strengthen the customer return path so a successful Midtrans payment reliably reconciles into the existing V14.3 fulfillment and entitlement boundary.

## Changes

1. Customer-return reconciliation now server-verifies both `CREATED` and `PENDING` commercial payment states.
2. A browser redirect is never trusted as payment truth; Midtrans Get Status remains authoritative for the return-path reconciliation.
3. Existing paid orders continue through the idempotent V14.3 fulfillment boundary when access has not yet been fulfilled.
4. The payment success page automatically refreshes for a short bounded window while payment or fulfillment is still processing, reducing the chance that a customer remains on a stale locked state after settlement.
5. Existing Access & Plans entitlement rendering remains database-backed: owned access is `Sudah dimiliki` and disabled; unowned access remains `Beli`.
6. No database migration is introduced.

## Customer contract

`Beli` → Midtrans → settlement → `/checkout/success` → server-side reconciliation → fulfillment → entitlement → Access & Plans unlock.

## Security invariant

The redirect query parameters remain informational only. ReadyScore verifies order ownership, provider reference, amount, currency, and current provider status before marking payment paid or fulfilling access.
