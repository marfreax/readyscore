# ReadyScore V18.0 — API Contract Lock

## Admin

```text
GET  /api/admin/whatsapp/conversations
GET  /api/admin/whatsapp/conversations/:id
GET  /api/admin/whatsapp/conversations/:id/messages
POST /api/admin/whatsapp/conversations/:id/messages
POST /api/admin/whatsapp/conversations/:id/read
POST /api/admin/whatsapp/conversations/:id/link-lead
GET  /api/admin/whatsapp/conversations/:id/lead-candidates
```

All admin routes reuse existing ReadyScore authentication and authorization.

## Webhook

```text
GET  /api/webhooks/whatsapp
POST /api/webhooks/whatsapp
```

## Response Contract

Existing ReadyScore response conventions remain authoritative. Successful API responses use the existing `ok/data` pattern where the surrounding route already uses it. V18 must not introduce a second global envelope.

## Error Contract

Expected operational error codes include:

```text
WHATSAPP_PROVIDER_NOT_CONFIGURED
WHATSAPP_AUTH_FAILED
WHATSAPP_PHONE_NOT_FOUND
WHATSAPP_RATE_LIMITED
WHATSAPP_TEMPLATE_REQUIRED
WHATSAPP_PROVIDER_REJECTED
WHATSAPP_NETWORK_ERROR
WHATSAPP_UNKNOWN_ERROR
WHATSAPP_CONVERSATION_NOT_FOUND
WHATSAPP_RECIPIENT_INVALID
```

Webhook-specific validation errors remain explicit and must not expose secrets.

## Authorization

- unauthenticated admin request: `401`
- authenticated without privilege: `403`
- missing conversation: `404`
- validation/provider operational errors: route-appropriate `4xx`
- unexpected server failure: `5xx`
