# ReadyScore V18.0 — Security Contract Lock

## Secrets

Server-side only:

```text
WHATSAPP_ACCESS_TOKEN
WHATSAPP_VERIFY_TOKEN
WHATSAPP_APP_SECRET
WHATSAPP_PHONE_NUMBER_ID
WHATSAPP_GRAPH_VERSION
```

Never:

- return secrets to browser;
- log secrets;
- persist secrets in database;
- commit secrets;
- include secrets in screenshots or test output.

## Webhook

- GET verification requires `hub.mode`, `hub.verify_token`, and `hub.challenge`.
- POST requires `X-Hub-Signature-256` validation using the server-side app secret.
- HMAC comparison must remain timing-safe.
- malformed payloads must fail safely.
- unknown events must not expose secret material.

## Admin

Reuse existing ReadyScore admin authentication/RBAC. No second authorization system.

Protected actions:

- view conversations;
- view messages;
- send messages;
- mark read;
- link BusinessLead.

## Logging

Allowed operational identifiers:

```text
conversationId
messageId
providerMessageId
event type
status
provider error code
```

Forbidden:

```text
access token
app secret
verify token
full webhook signature
password
session cookie
```

Phone numbers should be masked in operational logs where practical.

## Data Safety

No historical WhatsApp data or ReadyScore data may be deleted to make a test pass. V18.0 performs no production DB mutation.
