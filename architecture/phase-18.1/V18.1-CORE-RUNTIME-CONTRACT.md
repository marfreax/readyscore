# ReadyScore V18.1 — WhatsApp Core Runtime Contract

## Status
Development implementation baseline. V18.1 is not production-certified by this artifact alone.

## Baseline
Built directly from the V18.0 Architecture & Baseline PASS source.

## Implemented Core Runtime Changes

### 1. Webhook boundary
- Existing Meta verification and HMAC signature validation are preserved.
- Existing signed payload normalization and persistence path are preserved.
- Unknown/unsupported event content remains safely non-fatal.
- Existing synchronous persistence is retained intentionally so accepted events are not acknowledged before durable persistence; latency certification remains part of V18.3.

### 2. Inbound identity
- WhatsApp phone numbers continue to use the canonical ReadyScore `normalizeWhatsAppPhone()` representation.
- BusinessLead matching now accepts the canonical `+62`, international `62`, and national `0` representations without creating a second identity system.

### 3. Inbound idempotency
- `WhatsAppMessage.externalMessageId` remains the provider-event uniqueness boundary.
- Duplicate inbound webhook delivery remains safe under the existing unique constraint and race handling.

### 4. Outbound idempotency
- `WhatsAppMessage.clientRequestId` is added as an additive nullable unique field.
- Admin send requests may provide `Idempotency-Key`.
- Repeating the same idempotency key for the same outbound conversation returns the existing message rather than sending another provider request.
- A conflicting idempotency key cannot be reused across a different conversation or direction.
- The admin composer generates a unique request key per send operation.

### 5. Provider boundary
- Existing `WhatsAppCloudApiClient` remains the only admin outbound provider boundary.
- Existing provider error mapping and secret handling are preserved.
- Existing `WHATSAPP_E2E_MODE` remains available for deterministic local provider simulation.

### 6. Delivery status
- Existing provider status processing remains responsible for SENT, DELIVERED, READ, and FAILED state persistence.
- Stale normal lifecycle updates are rejected.
